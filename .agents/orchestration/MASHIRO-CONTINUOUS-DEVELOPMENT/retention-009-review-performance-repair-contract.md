# RET bounded performance repair contract

2026-09-08 independent review guidance, following [actual candidate REPAIR](retention-009-review-candidate-v1-repair.md). This is an engineering route, not a change to the user's capacity or trash policy.

Use the existing accepted-version ledger for incremental logical byte totals. Only a successful trusted acceptance transaction changes object version/hash/accepted byte count and the total; an external editor never silently changes accepted bytes. Quota admission and receipt remain in the synchronous atomic apply chain. UNKNOWN is not zero; reductions/nonpersistent operations retain their established exceptions.

Startup and relevant invalidation set measurement UNKNOWN and schedule bounded full verification in batches that yield to the event loop. Snapshots return the current ledger/status promptly without a complete synchronous body scan. Each audit result must CAS the captured accepted version/hash, zone, staging generation and source/permission/governance generation before becoming KNOWN. A stale completion cannot clear newer dirty state or resurrect deleted/withdrawn content.

Filesystem watch is an invalidation hint only. It cannot grant KNOWN or establish that no changes occurred. To retain the established direct deletion/tamper-before-synchronous-accept counterexamples, the initial minimal cache route additionally checks the cached file identity and high-resolution change metadata before using cached admission state. Missing file or changed dev/ino/size/mtime/ctime immediately marks UNKNOWN and queues full hashing. Do not describe unchanged metadata as a fresh hash verification. Periodic bounded full hashing is still needed for unobserved changes, and every model-facing body read retains the existing trusted hash validation. Measure this metadata path at the actual 25,599-object scale; if it remains a multi-second synchronous scan, stop this route and use an asynchronous preflight/token boundary rather than layering more synchronous work.

Acceptance: preserve the original damaged/missing-body, UNKNOWN quota, over-limit reduction, cross-source revoke/delete, policy CAS and idempotent receipt tests; add same-size edits, restored modification time, replacement identity, deliberately absent watch event, stale audit after correction/deletion, shutdown during audit, and restart-before-first-audit. State exactly when COMPLETE means a verified accepted snapshot rather than a fresh physical scan. If an adversarial file replacement leaves all measured identity metadata unchanged, cached metadata cannot prove integrity; do not silently claim that case is covered. Confirm the original integrity contract before accepting any such weakening.

Record constructor, snapshot, guarded accept and event-loop responsiveness on the retained near-default-capacity synthetic dataset. No arbitrary microsecond target or broad framework rewrite is required; the demonstrated six-to-ten-second stalls must be removed. Keep old timing and failure evidence immutable. Root chooses and records the final route; reviewer does not edit the implementation.
