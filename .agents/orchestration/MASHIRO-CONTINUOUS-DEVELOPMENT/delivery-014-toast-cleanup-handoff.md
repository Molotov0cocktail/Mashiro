# Delivery 014 owned Toast activator cleanup handoff

The previous approved internal installer was uninstalled through its ordinary NSIS UI. It removed the installed program, Mashiro login registration, shortcut, and uninstall registration while preserving all 16 runtime data files and an unknown synthetic install-directory file. Two Mashiro Toast COM registrations remained under `HKCU\\Software\\Classes\\CLSID`, each with `LocalServer32` pointing at the deleted installed executable. The predecessor native result is preserved in `delivery-014-uninstall-comparison-01.json` and remains a repair finding.

The candidate extends `build/installer-login-cleanup.mjs` with an uninstall-only Toast activator cleanup. It enumerates direct CLSID children and opens only each `LocalServer32` key. It deletes the unnamed value only when its type is `REG_SZ` and its complete value exactly equals the installed executable path, either unquoted or with one surrounding quote pair. It then removes `LocalServer32` and the CLSID parent only when each key is empty. Values with arguments, prefixes, another path, malformed quotes, or `REG_EXPAND_SZ` are left intact. Named values and child keys are also left intact. Removing a parent repeats the current enumeration index so adjacent owned keys are both examined.

The focused Windows oracle compiles the real generated NSIS with warnings treated as errors, installs and runs the silent uninstaller against a unique HKCU test subtree, and cleans only that subtree. It proves two adjacent exact registrations and one quoted registration are removed; all foreign and malformed registrations remain; extra named values and child subkeys remain; and NSIS registers are restored. Existing login-uninstall and independent boundary tests ran in the same group. The result is 3 files and 16 tests passed. Project typecheck plus scoped lint and format checks also passed.

This is a focused candidate, not an overall Windows delivery pass. An independent reviewer still needs to inspect and run the candidate. After the retention candidate is integrated, the package must be rebuilt from a frozen output and an actual uninstall must prove that every exact Mashiro activator registration is removed while runtime data and unknown files remain intact.
