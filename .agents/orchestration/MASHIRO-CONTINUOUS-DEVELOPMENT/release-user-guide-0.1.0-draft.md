# Mashiro v0.1.0 安装、升级与恢复说明（草稿）

> 本文尚未发布。它依据当前产品入口、[014 Windows 数据与交付合同](../../../doc/tasks/014-windows-data-and-delivery.md)、[016 整体验收合同](../../../doc/tasks/016-overall-product-acceptance.md)和[发行说明草稿](release-notes-0.1.0-draft.md)编写。发布前必须补入最终下载地址、源码提交、安装包与附件的 SHA-256，并完成文末所列的最终制品核对。

Mashiro v0.1.0 面向 Windows 11 x64，是按当前 Windows 用户安装和运行的本机优先桌面应用。程序文件与业务数据分别管理：卸载或更换程序时，已选择的数据集应继续保留。

## 安装前准备

1. 从最终发布页下载 `Mashiro-0.1.0-win-x64-setup.exe` 和 `SHA256SUMS.txt`。发布前此处需替换为实际下载链接。
2. 用 Windows 的 SHA-256 校验结果与 `SHA256SUMS.txt` 对照。文件名相同不代表内容相同；校验值不一致时不要运行安装器。
3. v0.1.0 当前按未签名发行准备。最终发布说明会写明实际签名状态。Windows 可能显示未知发布者或按本机安全策略阻止运行；不要关闭 Windows Defender、SmartScreen 或单位安全策略。来源或校验无法确认时应取消安装。
4. Mashiro 不附带模型服务的 API Key。使用第三方模型服务可能产生由该服务收取的费用。

## 安装与首次启动

1. 运行安装器，选择程序目录。安装器使用当前 Windows 用户权限，不要求管理员提升。程序目录可以包含中文和空格。
2. 安装完成后启动 Mashiro。首次启动会出现“设置 Mashiro 数据位置”，此时再选择数据目录：

   - **使用默认数据位置**：使用当前 Windows 用户的默认数据目录。
   - **选择已有数据集**：打开已经由 Mashiro 创建且可校验的数据集。
   - **选择新数据位置**：选择一个空文件夹并建立新数据集。

   程序目录与数据目录可以不同。如果安装目录对当前用户可写，也可以选择安装目录下的 `data` 文件夹。数据路径可以包含中文和空格。

3. Mashiro 会以日常普通用户权限检查所选目录、数据集身份、数据库和写入能力。检查失败时不会悄悄换到默认目录，也不会新建一份空数据冒充原数据。
4. 创建助手后，在连接设置中填写 HTTPS 服务地址、模型和自己的 API Key，再将连接绑定到助手。开始对话前，请分别核对本机读取范围和实际模型服务可接收的资料范围。

## 找不到原数据时

如果原数据位置被移动、不可访问、权限发生变化，或数据集身份不匹配，Mashiro 会进入恢复流程。系统不会自行切换数据位置；选择“退出”或取消文件夹选择时，原指向会保留。成功执行重新定位、选择已有数据集或选择新数据位置后，用户选定的位置会成为当前数据位置。请按当前窗口提供的按钮操作。

看到“恢复 Mashiro 数据位置”时：

- 已知原数据被移动到哪里，并且窗口显示“重新定位原数据”：选择该项，再选择同一数据集现在所在的文件夹。
- 需要改用一份已有 Mashiro 数据集：选择“选择已有数据集”。
- “选择新数据位置”会在空文件夹中建立另一份新数据集，不是从原数据或备份恢复。成功后，当前数据定位会主动切换到这份新数据集。
- 不能确认数据来源或身份：选择“退出”，先检查磁盘、权限和备份。

这个“恢复 Mashiro 数据位置”窗口没有“从完整备份还原”按钮。需要使用备份时：

- 如果随后出现“数据启动准备未完成”，选择其中的“从完整备份还原”，再依次选择包含 `backup.json` 的备份文件夹和新的空数据文件夹；
- 如果应用仍能正常打开，使用 **数据与备份 → 从完整备份还原并重启…**；
- 如果原数据位置已经丢失、手上只有完整备份，而且当前只有“恢复 Mashiro 数据位置”窗口，可按下面的过渡步骤进入应用：
  1. 先记下窗口显示的原位置；不要删除或覆盖原位置和备份。
  2. 选择“选择新数据位置”，指定一个全新的空文件夹 A。系统会初始化一份新数据集并把当前定位切换到 A；A 只是进入应用所需的过渡数据集，不是备份恢复结果。
  3. 进入应用后，选择 **数据与备份 → 从完整备份还原并重启…**，再选择包含 `backup.json` 的原备份文件夹。
  4. 另选一个全新的空文件夹 B 作为恢复目标。B 不能是 A、丢失原数据的位置或备份文件夹，也不能覆盖其中任何内容。
  5. 确认恢复；只有恢复、治理核对和切换全部成功后，B 才会成为当前数据位置。保留 A、原位置记录和备份，直到确认恢复数据完整可用。

“数据启动准备未完成”还提供“重新选择数据”，用于返回位置选择流程。不要通过删除定位文件或手工创建空数据库来绕过恢复提示。这样会失去数据集身份核对，也不能恢复记忆正文、权限、删除抑制和业务回执。

## 完整备份

在应用顶部菜单选择 **数据与备份 → 完整备份并退出…**，然后选择一个空文件夹。确认后，Mashiro 会停止当前工作，创建并校验备份，再退出程序。

完整备份用于迁移和灾难恢复，包含数据库、已接受的 Markdown 记忆正文、来源与权限、删除抑制、业务和作业状态，以及受 Windows 当前用户保护的凭据材料。单独导出或复制 Markdown 文件不是完整备份。

建议在以下操作前创建完整备份：

- 安装新版；
- 更换数据位置；
- 进行可能影响大量数据的清理；
- 恢复或更换电脑前。

请把备份保存在与当前数据目录不同的位置，并保留与目标程序版本兼容的备份。不要让旧版程序直接打开已经迁移到不兼容新结构的数据集。

## 手动升级与同版重装

v0.1.0 采用“下载新版安装器并运行”的更新方式，界面不承诺自动下载或静默更新。

1. 在当前版本中选择 **数据与备份 → 完整备份并退出…**，等待“完整备份已完成”。
2. 核对新版安装器的来源、版本和 SHA-256。
3. 运行新版安装器，沿用当前程序目录。升级路径应保留现有数据位置和用户的登录启动选择。
4. 启动新版，使用 **数据与备份 → 查看当前数据位置** 核对数据目录，并检查助手、历史、记忆、事项、提醒和运行状态。

同版重装使用同一安装器；不要为了重装而删除数据目录。若升级未完成或新版无法安全打开数据，不要用旧程序直接尝试新结构；保留当前数据原位，并从兼容备份还原到新的空目录。

## 从完整备份恢复

应用可正常打开时，选择 **数据与备份 → 从完整备份还原并重启…**：

1. 选择包含 `backup.json` 的完整备份文件夹。
2. 查看备份时间和恢复提示。
3. 选择一个新的空数据文件夹作为恢复目标。
4. 确认后，Mashiro 会停止当前工作、校验备份、生成恢复副本，并在成功后切换到新位置重启。当前数据仍保留在原位置，不会被覆盖。

应用启动失败时，可在“数据启动准备未完成”窗口直接选择“从完整备份还原”，步骤相同。

恢复会应用本机仍能核验的后续删除、纠正和撤权记录。后来版本的正文无法取回时，系统不会用备份中的旧正文冒充。必要治理记录无法核验时，恢复会停止。恢复完成后：

- 连接和自动后台工作会暂停，请检查后重新启用；
- 自动记忆保留策略会显示“恢复备份后已暂停”，需查看影响并重新保存当前设置；后来明确关闭的策略仍保持关闭；
- 受保护凭据通常只能由原 Windows 用户使用；换用户或换电脑后应重新提供 API Key；
- 当前数据和备份都应继续保留，直到你确认恢复副本完整可用。

需要把当前数据整体移到新位置时，可使用 **数据与备份 → 复制到新数据位置并重启…**。该流程会先创建校验备份，再复制和切换；原位置继续保留。

## 卸载与重新安装

正常卸载用于移除 Mashiro 程序文件、快捷方式和属于当前安装的系统集成。业务数据默认保留，包括放在安装目录 `data` 下的数据；安装目录中的未知用户文件也不应被递归删除。

真正卸载会清理由当前安装拥有的登录启动登记；升级或同版重装应保留当前登录启动选择。卸载后重新安装并启动时，如果保存的数据定位仍然有效，Mashiro 会直接打开原数据，不会再次显示首次设置窗口；进入应用后先用 **数据与备份 → 查看当前数据位置** 核对。只有实际出现“设置 Mashiro 数据位置”或“恢复 Mashiro 数据位置”时，才选择“选择已有数据集”，或按上节使用“重新定位原数据”。确认新安装已正确打开原数据前，不要删除数据或备份。

这些行为仍须以最终 v0.1.0 安装包完成整套安装、升级、卸载和重装核对；本草稿本身不是完成证明。

## 窗口、托盘和提醒

- 点击主窗口关闭按钮会隐藏窗口并让 Mashiro 驻留托盘；同一进程继续检查已保存提醒。双击托盘图标，或在托盘菜单选择“打开 Mashiro”，可以重新显示窗口。
- 需要真正结束程序时，使用应用菜单中的 **数据与备份 → 退出 Mashiro**，或托盘菜单中的 **退出（退出后不再提醒）**。明确退出后，Mashiro 不承诺继续调度提醒。
- 已经投递给 Windows 的通知可能在退出后继续保留；点击有效通知可启动 Mashiro 并定位相应事项。业务已完成或取消时，相应通知应撤下。
- 默认补发最近 24 小时内仍未处理的提醒：同一事项只补最新一条，多事项可合并；更早的提醒进入过期待处理。已完成或取消的事项不补发，展示结果未知的通知不会盲目重复发送。
- 可在“提醒”的“运行与补发”中调整或关闭补发，选择是否合并，并设置“登录 Windows 后启动 Mashiro”。关闭主窗口与明确退出含义不同。

最终发布前仍需用最终安装包确认实际 Windows 通知展示、点击、程序未运行时的冷启动定位、托盘操作、登录启动和补发结果。

## API Key 与凭据

连接设置提供两种 Key 保存方式：

- **运行期临时 Key**：只在本次 Mashiro 进程中使用，明确退出或重启后失效。关闭窗口并驻留托盘仍属于同一次运行。如果该连接以前保存过持久 Key，临时 Key 只覆盖本次运行，重启后仍会恢复原持久 Key。
- **使用 Windows 凭据保护持久保存**：由当前 Windows 用户保护并可在重启后使用。Mashiro 不在界面重新显示 Key，也不把明文 Key 写入普通导出、日志或发布文件。

删除 Key 会删除该连接当前保存的凭据。完整备份可以保存受保护材料，但不会把它变成可跨用户使用的明文；跨 Windows 用户或换电脑恢复时应重新配置。

## 正常对话与严格临时对话

- **正常时间线**会把对话保存在本机，并按当前助手的权限决定可读取和可发送的历史、记忆、事项及其他资料。
- **严格临时**只保留在本次 Mashiro 运行中，不读取正常历史或记忆，不自动写入正常时间线，也不建立可在重启后恢复的正文或协议快照。明确退出或重启后，未保存的临时正文消失；仅关闭窗口并驻留托盘不会开始新运行。
- 如需保留临时会话，请在该会话中选择 **保存到此助手时间线**。Mashiro 只保存可信接纳的合格消息，并显示保存结果；未发送或被拒绝的草稿不会被标成已保存。
- 人设会随请求发送给界面显示的实际接收方，但人设本身不会授予历史、记忆、事项或工具权限。切换助手、连接、模式或权限后，迟到响应不能重新显示旧助手或已撤权的正文。

## 记忆保留和恢复

默认持久区按当前接受版本 Markdown 的 UTF-8 正文总量设置 100 MiB 上限；暂存记忆默认在进入暂存区 90 天后转入可恢复垃圾区。两项均可调整或关闭。垃圾区永不自动永久清空。

可在 **保留、恢复与清理** 中查看当前用量、核查状态、期限、最近运行结果和失败项。计量无法可靠完成时显示“未知”，不会按 0 继续接受新增占用。自动到期只把暂存对象移入可恢复垃圾区；永久清理必须另行查看完整影响并在本机确认。
