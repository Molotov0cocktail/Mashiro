# Login candidate v1 independent review: REPAIR

Root reviewed the frozen login candidate and the exact [Electron 44.1.1 Windows implementation](https://raw.githubusercontent.com/electron/electron/v44.1.1/shell/browser/browser_win.cc). This is a bounded repair finding, not a release verdict.

1. `GetLoginItemSettingsHelper` parses `options.path` as a Windows command line before matching executable paths (lines 185–197). Passing the unquoted `process.execPath` from the required Chinese/space installation directory can truncate the lookup program. The new strict `launchItems` check can consequently reject a successful registration. Quote the lookup path appropriately and validate against actual Electron behavior or a faithful command-line parsing oracle; retain the exact identity and arguments checks.
2. `SetLoginItemSettings` accepts `enabled` and writes a disabled startup state when false (lines 635–659). The candidate comment that Electron cannot restore the prior disabled state is unsupported. Restore the observed enabled/disabled semantics without claiming preservation of arbitrary original registry bytes.
3. `launchItems` only enumerates matching executable paths. A mock that returns an old different-path registration for the current lookup does not prove that production can discover and restore it. Keep the boundary explicit or use a bounded, accurately observed route; do not claim successful compensation from an impossible API fixture.

Actual Electron probe01 subsequently observed quoted lookup registered/effective with the exact item, while unquoted lookup remained `openAtLogin: true` but had no item and was ineffective. The probe's original assertion expecting otherwise failed and must remain historical evidence. It also observed `launchItems[].args: []` for an actual `--mashiro-login-probe-20260907` switch. Exact full-command equality is supplied by `openAtLogin`; the launch-item argument list cannot be treated as a complete switch-preserving command line or used to reconstruct unknown old flags. The author was given this additional concrete repair input. Future probe runs must use distinct evidence filenames and exact owned registry preimages before cleanup.

Author's 15 passing tests and native old-build observations remain historical evidence. The coordinator has returned these concrete findings to the single writer. No registry mutation or product edit was performed by this review, and no private notification content was accessed.
