# 014 治理恢复最终协议增补

本增补明确当前候选实现，配合原治理恢复合同阅读；它不是独立审核 PASS。

- SQL 采用 TEMP AFTER 行触发器。回调在业务提交前 fsync 最小投影，提交 token 与业务行同事务。INSERT/UPDATE OR IGNORE 未实际变更不留下已完成治理。结算失败不猜测 SQL 失败；原实例锚点与提交 token 才能结算在途记录。
- PREPARING 登记前持久写入随机命名、哈希绑定的无正文种子。未向服务暴露写连接时，初始化/经批准外来完整备份导入中断可重建未完成日志；部分日志保留为证据。READY 日志丢失或损坏绝不使用种子重建。已知 locator 对应 UUID 无日志不能当外来新库导入。
- 完整备份携带已结算最小投影及数据侧 journal 标识。相同配置有更新账本时以本地已知治理为准；显式验证的外来备份可登记其携带屏障。备份之后、未包含在备份且原配置侧账本也已丢失的治理无法凭空推断，不宣称此情况仍知晓所有删除。
- schema17 引入实例/token表；现整合 schema18 本轮来源表。迁移前校验不提前要求新18表。受治理17库升级时验证候选与原实例、版本、完整性及治理覆盖，候选旋转实例 UUID，并在原子替换之前持久登记新文件锚点。旧锚点仍可识别；不以宽松 inode 校验代替授权。新候选正式 session 重开及原生安装升级仍需最终独立验证。
- 恢复暂停连接、绑定与后台自动运行资格；读写和接收方权限取交集。后来取消/处理/已派发的提醒不复活；未变化正常提醒仍可继续。已完成、取消、失败作业保留历史状态，待继续/待接受资格失效，敏感候选及回执副本清理。
- 凭据采用非破坏撤销：恢复副本保留原加密文件，受管撤销标记阻止读取/解密；标记非普通文件、悬空链接、损坏或读取异常均拒绝。仅用户显式保存新持久 Key 后解除；临时 Key 仅本次临时有效。备份纳入标记哈希和结构校验。没有删除保护 blob，也不声称物理删除凭据。此前物理删除路线被自动审批拒绝两次，证据保留；本替代已获批准。

用户指南建议措辞：旧备份中的原加密凭据文件可能仍保留，但已撤销凭据在恢复后不可复用；请显式保存新的持久 Key 才能重新启用。临时 Key 仅临时可用。恢复后的连接与后台自动任务需重新确认配置。

本候选仅合成数据验证；没有新真实 Provider 请求。尚无本治理实现的原生完整恢复/安装生命周期 PASS，不能将单元或服务级测试冒称整体014完成。
