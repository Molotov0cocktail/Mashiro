## 1. 产品定位

Mashiro 是一款面向单用户、Windows 11、本机优先的私人助理桌面应用。持续日常对话是主要入口；应用通过长期记忆、可配置助手、事项与提醒、可配置 Provider，帮助用户理解和管理生活、学习与个人资料。

Mashiro 不是 Coding Agent，不重造完整浏览器，也不在当前阶段替代 AIbrowse 或 Clender。它应具备长期使用所需的清晰、舒适和可控性，但本次规划不冻结最终布局、主题、形象、动画或完整视觉系统。

## 2. 三层范围

### 2.1 完整产品愿景

- 支持多个助手；每个助手具有稳定身份、唯一持续时间线、独立关系与连续性记忆，以及可配置的人设、基础形象、Provider、模型和本地数据访问范围。
- 以可读、可编辑、可迁移的分支化 Markdown 保存长期记忆语义；由本地事务存储维护身份、来源、性质、权限、版本、生效状态、删除抑制、待整理状态和作业状态。
- 区分全局用户记忆、助手关系记忆、稳定人设、当前上下文、个人事件和 Provider 专属续接数据。
- 统一管理目标、项目、任务、承诺、等待事项和待确认提案；任务与日历时间块保持不同概念。
- 提供每日简报、晚间复盘、每周规划、截止与变更提醒，以及可配置、可预算、可观察的后台工作。
- 提供记忆来源、变更、纠正、删除、权限、压缩、运行状况、用量和业务操作历史。
- 后续按授权接入 AIbrowse、Clender、邮箱、AnxReader、游戏记录、观影笔记、日记、项目文件及其他指定数据源。

### 2.2 首个日常可用版本

首个日常可用版本以“核心私人助理”为范围：

1. 持续对话与基础多助手；
2. 自定义真实 OpenAI-compatible Provider；
3. 可控的初级长期记忆；
4. 统一事项、待确认提案、承诺管理；
5. 应用或托盘运行期间的基本主动提醒与恢复补发；
6. 必要的权限、用量、运行状况和错误说明。

这是产品里程碑，不是单次初始化任务。AIbrowse、Clender、邮箱、日记等真实集成后置。

### 2.3 本次工程初始化

本次初始化尚未获授权，最小闭环也尚未最终选择。候选、依赖与推荐见 [001-project-foundation.md](tasks/001-project-foundation.md)。

初始化只应验证一个真实、甄别性的产品基础行为以及相应工程链路，不一次实现首个日常可用版本。无论选择何种闭环，都不得顺带启动真实 Provider 验证、个人数据接入、完整记忆系统、正式提醒后台、安装更新系统或跨应用串联。

## 3. 核心用户场景

### 3.1 与稳定助手持续交流

- 用户创建、切换、重命名、归档助手并指定主助手。
- 改名、换基础形象或更换 Provider/模型不产生新助手、不丢失时间线、不清除关系记忆。
- 归档不等于删除，也不连带删除已经进入全局状态的正式事项、承诺或共享记忆。
- 正常情况下每个助手只有一条持续时间线；上下文可以分章、压缩和检索，不等于每次发送完整历史。
- 多个助手不会自动互读完整聊天或关系记忆；全局用户记忆按权限共享。

### 3.2 严格临时交流

- 使用所选助手的稳定人设与 Provider，但不自动读取正常时间线、关系记忆、全局用户记忆或私人业务上下文。
- 不写入正常时间线，不生成长期记忆、事项、提案、提醒或其他持久化业务操作。
- 正文不进入 Mashiro 的持久化运行日志或后台摘要；必要协议续接数据只在内存中保留。
- 用户若要保存，必须通过清晰的切换或保存流程；Mashiro 不承诺远端 Provider 零留存或系统级安全擦除。
- “读取既有上下文但本次不留档”和“保留聊天但不提炼长期记忆”是不同的后续候选，不与严格临时模式混称。

### 3.3 理解和管理记忆

- 用户明确要求记住、纠正或删除时，在权限允许范围内直接生效，提供回执与适用的撤销入口。
- 用户陈述和不增加新断言的忠实归纳可低干扰自动保存；新增推断保持推测或待核验性质。
- 默认收起的来源与变更面板可检查本轮提供给模型的记忆、本轮变更、来源、时间、性质和操作入口。
- 纠正或删除后的旧结论退出正常召回，并受防复活规则约束。
- 记忆和个人事件分为持久保留区、暂存区和垃圾区；分区只表达保留策略，不改变事实性质、权限或归属。

### 3.4 管理事项与提案

- 目标、项目、任务、承诺和等待事项进入统一正式事项系统，同时保留各自类型和生命周期。
- 用户明确要求创建或修改时，按权限政策低干扰执行；删除、批量或高影响操作遵守对应确认规则。
- AI 推测的潜在事项保存为待确认提案，可确认、否决、暂不处理或与发起助手协商修改。
- 提案在确认前不计入正式统计、不触发正式执行提醒、不占用日历时间，也不能被描述成用户已经承诺。
- 严格临时模式不自动生成持久化提案。

### 3.5 获得可靠提醒

- 应用打开、最小化或驻留托盘时可提供提醒；用户可选择登录启动。
- 休眠恢复或重启后，对仍有价值的逾期提醒受控补发；明确退出后不承诺继续提醒。
- 未接入 Clender 前，Mashiro 可管理事项及提醒并给出时间建议，但不能声称已写入日历、已核实空闲或不存在冲突。

### 3.6 配置和观察 Provider

- 多个可复用连接配置分别保存连接身份、端点和凭据；助手模型选择独立于连接配置。
- 首批重点兼容 DeepSeek、GLM，并审查 Qwen、Kimi 差异；MiniMax、Gemini、Claude 先记录限制和后续适配需求。
- 能力区分官方声明、本地协议测试与用户真实端点验证。真实验证必须绑定接收端点、协议、模型/版本、模式和适配版本。
- 普通响应、流式、思考、工具、结构化输出和用量是独立能力，不能用一次聊天成功替代完整资格验证。

## 4. 产品约束

### 4.1 本地权威

- 单用户、本机个人数据为权威；首版不要求产品账号、自建服务器或跨设备同步。
- 远端模型只接收“任务需要、当前读取权限允许、目标接收方获准”三者交集中的数据。
- 本地时间线和本地上下文构建维持连续性，不依赖远端 conversation 或 `previous_response_id` 成为权威。

### 4.2 隐私与权限

- “助手允许读取”和“允许向某个 Provider 发送”是不同权限维度；更换模型不能静默扩大外发范围。
- 原文、摘要、派生记忆、历史回答、embedding、后台整理和协议扩展均受同一来源与外发边界约束。
- 默认运行日志不复制聊天、记忆、邮件、日记、请求响应正文，不记录密钥或认证信息。
- Windows 保护的持久凭据与本次应用运行期临时凭据并存；系统保护失败时不得降级为明文落盘。

### 4.3 数据可理解与可恢复

- 记忆正文、来源、性质、时间范围、不确定性、有效状态和删除意图应可解释。
- 原文整理回收与删除信息/撤回依据是不同操作；只删记忆不等于删除全部历史痕迹。
- 保存、恢复、重试和压缩不能覆盖用户在其间作出的修改、纠正、删除、取消或权限变化。

## 5. 非目标

当前阶段明确不做：

- 修改、迁移或真实连接 AIbrowse 与 Clender；
- 读取真实邮箱、日记、个人资料库或其他未授权私人数据；
- 多助手自动并行、互相说服或通用 Agent 调度平台；
- 任意 Provider 请求模板、脚本、自定义协议编辑器或大型多 Provider 框架；
- 完整浏览器、正式日历替代品或第二套竞争性日程状态；
- 跨设备同步、多用户、网络盘并发写入或自建后台服务；
- 在本次初始化中完成完整安装器、更新器、卸载器、数据迁移或最终视觉系统；
- 从阅读、观影、游戏或临时情绪静默推断确定性人格或心理诊断。

## 6. 阶段验收

### 6.1 首个日常可用版本的可观察验收方向

- 用户可恢复指定助手的持续时间线，并能明确进入严格临时模式。
- 连接配置、模型选择、能力与数据外发授权可辨认，失败不静默切换接收方。
- 用户能查看、纠正、删除记忆并理解来源和生效状态。
- 用户能管理正式事项和待确认提案，提醒承诺与应用运行状态一致。
- 后台整理、权限拒绝和业务操作的状态、用量及失败可被理解和恢复。

具体用例和数值阈值在对应任务中冻结，不以本 Proposal 代替任务验收。

### 6.2 初始化验收方向

- 一个真实行为贯通 Electron main、preload、renderer 和必要的可信存储边界；
- 至少一个甄别性测试证明该行为，而非仅断言 mock 被调用；
- 安装、测试、类型检查、lint、格式、构建和启动结果均来自实际执行；
- 文档、实际命令和现场状态一致；
- 未触碰真实个人数据、参考项目和未授权外部服务。

## 7. 外部依赖与后续边界

- AIbrowse 保留浏览器和研究能力；未来可提供简单工具调用、复杂任务委托和统一记忆增量提交，但协议尚未冻结。
- Clender 保留日程展示、保存、手动调整和确定性校验；未来 Mashiro 直接规划并在授权下修改唯一日历状态，当前不迁移或改造。
- embedding 仅是可选、可重建的语义检索派生物，不判断事实真假，不取代 Markdown 或来源状态。
- 打包器、安装器、更新器、Windows 凭据机制、数据库实际驱动和 Provider 客户端实现均须按任务重新核验。
