## 应有用户闭环

1. 用户在正常对话明确要求记住、纠正、删除记忆表示或撤回依据，按已确认意图和当前助手领域权限进入即时有效路径，得到可信操作回执；无需等待仓储员。删除表示、撤回依据及其抑制范围须由S0对照原文冻结，不能借此静默永久删除助手、自动清空垃圾或连带删除正式事项。随后有权助手在任务需要且接收端点获准时召回正确版本或观察对应内容不再召回。模型自述不构成已保存/已删除证明，失败不能显示成功。
2. 全局用户记忆与助手私有关系/连续性记忆有明确归属。正文为Markdown语义内容，来源、时间、性质（用户陈述/忠实归纳/推测）、版本、生效/待整理状态、读取/外发范围和用户抑制由可信治理状态保存。个人事件记录支持与记忆不同的时间/状态语义，不把正式事项或提醒当成事件。
3. 日常界面可查看、搜索、编辑、纠正记忆与个人事件；来源和变更默认收起，按需展开能定位正常对话原轮次。用户修改优先于旧版本作业与恢复。用户明确删除表示和撤回依据应区分，不能悄悄抹除全局事项或原文，也不能被旧来源/索引重建复活。
4. 助手读取与Provider接收分别授权，每次上下文构建和工具提交重新检查当前交集；跨助手私有记忆不泄漏，更换端点不继承新接收权。严格临时不读写任何正常记忆/事件/业务/待整理记录；显式保存临时聊天不能顺带复制内部协议或打开新领域权限。
5. 忠实归纳与新增推测保留不同性质。直接路径的有效数据可以立即使用；适合全局归并的增量有真实待整理记录与来源，不用空占位界面伪装仓储员已完成。完整自动仓储/章节/观察/习惯/简报由Q9接续，验收去处继续保留在总清单。

- 定义全局记忆、助手关系/连续性记忆、个人事件、来源/抑制与变更记录的最小版本化数据模型及中文入口。范围、性质和权限不能从Markdown正文或不可信frontmatter自动扩大。
- 扩展同一领域读取/实际端点接收契约，以及清晰可见的业务写入权限/本轮意图。工具能力与领域授权分别判断；模型自由文本不是最终可信批准。当前工具选择DTO可按工程需要演进，但保留旧正常/临时与上下文选择行为。
- 为Markdown和SQLite选择可核查的跨资源提交方法。例如先安全保存不可变版本正文，再用SQLite事务切换接受版本和成功回执；失败/中断保留可恢复意图，未接受的孤立文件不参与召回。具体方案由执行链依据实测冻结，不能宣称SQLite使文件系统原子化。
- 用户纠正/删除抑制、当前版本检查必须先于旧任务重试、索引恢复和外部Markdown重新载入。应用内编辑为首版主路径；外部编辑需要显式重新载入、差异和可信验证，不静默采用来源/权限变化。
- 全文索引须可重建，坏索引不能删除有效正文。可选向量能力按原文范围，不伪称已实现。提供完整数据备份所需的版本/治理文件清单；单独Markdown导出不称为完整备份。
