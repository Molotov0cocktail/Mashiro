# 019 安装启动与测试数据隔离修复

状态：ACTIVE。基线 d377117，v0.1.0 已发布事实保留；2026-09-08 用户实际反馈重新开启修复，不沿用旧 PASS 排斥新缺陷。

## 问题与验收

- 桌面自定义安装后出现泛化启动错误：定位实际最早失败原因，在隔离桌面子目录、默认目录、中文空格目录验证；不得将用户桌面根目录当作可递归清理的应用目录。
- 默认重装仍指向之前合成测试数据：证明安装包是否带数据、是否为本机 locator/治理元数据残留；保护正常升级保留真实数据语义，测试配置必须与正式使用隔离，不能仅隔离数据库而共用定位与治理目录。
- 为用户提供清晰、可恢复的数据位置查看/新建/切换入口；失败提示给出可操作原因，不静默重建空库或覆盖原数据。
- 当前测试残留仅在元数据证明归属后处理；保留原数据可恢复副本，不读取无关私人内容，不删除用户安装后可能新增的业务数据。
- 持久凭据、治理记录和删除抑制不得因切换/迁移丢失或混用。
- 修复后独立复核、实际安装生命周期验证、更新版本并发布核验；不替换 v0.1.0 已发布资产。
